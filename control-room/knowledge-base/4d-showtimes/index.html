Overview

The 4D Showtimes system is the most interconnected of the current signage CMS applications. It separates reusable content from day-by-day scheduling: films define what guests are seeing, load templates define reusable patterns of showtimes, daily schedules tie a film and optional load to a calendar date, and concrete showtime rows determine the actual times for that date.

Daily Quick Start

For an ordinary single-day schedule, the safest sequence is: select date → select film → select/apply load → review times → save pending changes → publish → verify.

Sign in.

Use an authorised 4D Showtimes admin account. The app persists the Supabase Auth session and attempts to restore it when the page is reopened.

Select the working date on the calendar.

The selected date loads its draft schedule, live schedule, draft showtimes, live showtimes, assigned film and assigned load. The app remembers the last selected date per signed-in user.

Select the Featured Film.

Only active films are offered. Changing the film in normal single-date mode immediately creates or updates that date's draft film assignment.

Select the Assigned Load and preview its times.

Only active loads are offered. The preview shows the reusable time pattern before it is applied. After-hours template times are visually distinguished.

Choose Apply Load to Draft.

This generates or refreshes the draft from the selected Film + Load. If the date already has active draft showtimes, the editor warns that those draft times will be replaced.

Review or manually adjust Draft Showtimes.

Change the hour/minute/AM-PM controls, add a showtime or delete an unwanted time. A manual change marks the draft as manually modified rather than purely load-generated.

Make sure every changed row says Saved.

Time edits auto-save shortly after a change, and each row also has Save Now. Use Save Pending Showtimes before publishing whenever any rows still show an unsaved state.

Review Day Summary.

Confirm the date, Film, Load, showtime count, Manual Edits state, Last Updated timestamp and Last Published timestamp before taking the schedule live.

Choose Publish.

The editor first attempts to save any pending showtime changes. Publishing requires a draft, a film assignment and at least one active showtime. After confirmation it publishes that date live.

Verify the live 4D display.

The guest-facing page rechecks its consolidated Supabase data every 10 seconds. When publishing the current Vancouver date, a successful change should therefore normally appear quickly.

Single-date publishing has a useful safety net: before the publish RPC runs, the editor calls Save Pending Showtimes silently and refuses to publish if any changed showtime row could not be saved.

Calendar & Day Status

The calendar is both a date picker and a high-level status dashboard. For the visible calendar month, the admin reads schedule state from daily_schedules and decorates each date accordingly.

Status

No Draft / Draft / Live

The header and Day Summary use the three-state meter. If a live schedule exists, the date is presented as Live even when a draft also exists for future edits.

Manual Changes

Manual Edit Indicator

Dates whose draft has has_manual_edits = true receive a separate calendar indicator. Day Summary describes the state as “Yes — manually modified” rather than “No — load-generated.”

Load

Load Colour Dot

When the schedule is associated with a load template, a small dot uses that load's display colour. Its tooltip identifies the load name.

Batch Selection

Long-Press a Date

Holding a calendar date for approximately 1.5 seconds enters Batch Editor mode. Once batch mode is active, additional dates can be toggled into or out of the batch with ordinary taps.

The admin also stores each signed-in user's Night Mode preference and last selected date in local browser storage. These are convenience settings, not schedule data.

Single-Date Editor

Featured Film

Selecting a film writes that film assignment into the current date's draft. If no draft exists yet, the editor can create the draft record as part of this workflow.

Assigned Load

Selecting a load only changes the load preview until Apply Load to Draft is chosen. Merely choosing a different load in the dropdown does not itself regenerate the schedule.

Apply Load to Draft

Calls the database helper generate_draft_schedule_from_load with the selected date, film and load template. Existing active draft showtimes are replaced after confirmation.

+ Add Showtime

Adds a new concrete daily_showtimes row. When other active draft times exist, the default is 20 minutes after the latest one; otherwise the default begins at 10:30 a.m.

Change a Showtime

Changing hour, minute or AM/PM marks the row unsaved and schedules an automatic save after about 650 milliseconds. Each row also has Save Now for an explicit immediate write.

Delete Showtime

Permanently removes that draft showtime row after confirmation and marks the draft schedule as having manual edits.

Save Pending Showtimes

Iterates through only the currently unsaved showtime rows, attempts to save each one, and reports the number saved versus the number still requiring attention.

Publish

Requires a selected date, an existing draft, a film assignment and at least one non-cancelled showtime. The action auto-saves pending rows before invoking the database publish helper.

Applying a Load is a replacement operation. Use it to regenerate a draft from the template. Do not choose Apply Load after carefully hand-editing a date unless you intend to replace those draft showtimes with the template pattern again.

Batch Editor

Batch Editor is designed for efficiently preparing several dates with the same film and load template. It should be treated as a generation tool, not merely a multi-date “publish existing drafts” tool.

Long-press a calendar date for approximately 1.5 seconds.

This enters Batch Editor and makes that date the first selected batch date.

Tap additional dates.

Each tap toggles the date into or out of the selected batch.

Select the film to use for the batch.

While Batch Editor is active, changing the Film dropdown changes the batch selection state rather than immediately writing a single-date film assignment.

Select the load to apply to all selected dates.

The batch requires both a Film and a Load before it can be saved or published.

Choose Save Drafts and Close — or Publish Selected Dates Live.

Saving generates/replaces drafts for all selected dates and exits Batch Editor. Publishing first generates/replaces those drafts and then publishes every selected date.

Critical Batch Editor rule: Publish Selected Dates Live does not simply publish each date's existing draft. It first calls the load-generation workflow for every selected date using the currently selected Film + Load, which can replace existing draft showtimes, and only then publishes those regenerated drafts.
Save Drafts and Close is also a replacement operation. The confirmation message explicitly warns that existing draft showtimes on the selected dates will be replaced. Use Batch Editor only when those dates are intended to share the selected Film + Load pattern.
Individual showtime editing is disabled while Batch Editor is active. Finish the batch with Save Drafts and Close (or publish it) before hand-editing individual times.

Film Manager actions

Save Film Details

Requires a non-empty film title. Saves the metadata fields, normalized poster code, active flags for messages/accessibility items and theme information.

Sample from Poster

Loads the medium poster image in the browser, samples/quantizes its colours and proposes two visually distinct theme colours. The result remains unsaved until Film Details is saved.

Swap Colours

Exchanges the Primary and Secondary theme colour values before saving.

Create New Film

Prompts for a title and creates an active film with blank guest-facing content and default theme values.

Duplicate Film

Creates a new active film using the selected film's synopsis, messages, accessibility content, poster code and theme colours as the starting point.

Delete Film

Permanently attempts to delete the selected films row after confirmation. Historical schedules reference films through a foreign key, so deactivation is generally the safer operational choice when a film should simply stop appearing in the scheduler.

Film Manager tracks whether the current form has unsaved changes and asks before discarding those changes when switching away from the edited film.

Load Manager

A Load is a reusable theatre-intensity/showtime template. The parent record lives in load_templates; its individual time rows live in load_template_times. Applying a Load to a date expands those reusable time rows into concrete daily_showtimes.

Load types and colours

Load kind Current manager behaviour
green Uses fixed VAQ green #7d9b2d.
yellow Uses fixed yellow #f3bc43.
red Uses fixed red #c73232.
custom Allows a custom display colour and is used for newly created / duplicated non-default loads.

Default-load protection

The live Load Manager distinguishes system-default loads from ordinary/custom loads. A system-default load is locked by default: its details and showtime controls cannot be changed until Edit Default is explicitly enabled. System-default loads also cannot be deleted.

Safer practice: when a standard/default Load needs a one-off variation, Duplicate Load and modify the duplicate instead of unlocking and changing the system default used by other dates.

Template Showtime behaviour

Change a time

Hour/minute/AM-PM edits auto-save after about 650 milliseconds and can also be saved immediately. Duplicate times within the same Load are rejected.

+ Add Showtime

Adds a new template row. When times already exist, the default new time is 20 minutes after the latest template time; otherwise it begins at 10:30 a.m.

After-hours flag

Load Manager automatically sets is_after_hours when a template time is 5:00 p.m. or later.

Duplicate Load

Creates a new non-default Custom Load and copies all of the selected Load's template time rows.

Delete Load

System-default loads are protected. For an eligible non-default load, the manager first deletes its template-time rows and then attempts to delete the load itself.

Historical or current daily_schedules can reference a load template through applied_load_template_id. If a load has been used by schedules, database foreign-key rules may prevent deletion or otherwise require careful handling. Deactivation is safer when the goal is only to stop offering a Load for new schedules.

Publishing Rules

Draft and Live are separate daily schedule records.

daily_schedules.status is constrained to draft or live. A selected date can therefore retain a draft for editing while a live version remains guest-facing.

Single-date Publish auto-saves pending time edits.

The editor refuses to proceed if any pending showtime change reports a save error.

Publish readiness is intentionally simple.

A single date is considered publishable when it has a draft, an assigned film and at least one non-cancelled showtime.

Batch Publish regenerates first.

Batch publishing applies the selected Load + Film to every selected date before invoking publish_daily_schedule for those dates.

Manual edits are tracked.

Adding, changing or deleting individual draft showtimes sets has_manual_edits = true. The Day Summary and calendar surface this distinction.

Live display follows Vancouver time.

The public renderer is explicitly anchored to America/Vancouver for time-of-day logic, including the after-hours gate.

Showtime filtering

  • Cancelled showtimes are excluded.
  • Only showtimes later than the current moment remain in the visible future-showtime list.
  • The earliest remaining displayable showtime becomes the “Next show” tile.
  • The showtime grid dynamically changes its column count and font sizing based on how many future times remain.
  • As showtimes pass, the renderer animates/reflows the remaining times without requiring a full page reload.

After-hours gate

The renderer has a 5:00 p.m. Vancouver-time gate for later showtimes. Before 5:00 p.m., showtimes after 5:00 p.m. are hidden from the public list. When hidden after-hours times are the only remaining shows, the sign displays “More showtimes later today” and asks guests to check back after 5:00 p.m.

5:00 p.m. itself is a special case. Although Load Manager marks times at 5:00 p.m. or later as after-hours, the public renderer explicitly does not hide a showtime scheduled at exactly 5:00 p.m. before the gate. Times later than 5:00 p.m. remain hidden until the gate opens.

Accessibility, advisories and testimonials

  • Up to five active recognised accessibility items are rendered as icons.
  • Active advisory messages rotate every 9 seconds when more than one advisory exists.
  • Active testimonials interrupt the accessibility region approximately once per minute.
  • A testimonial remains visible for about 9 seconds, after which the accessibility icons return.
  • If no future displayable showtimes remain, the supplemental rotations are stopped and an end-of-day state is shown.

Film theme

The public display applies theme_color_primary and theme_color_secondary from the live film data as CSS variables, allowing the sign to visually follow the selected film's poster palette.

Data & Supabase

The August 25, 2026 schema summary identifies five core application tables. All use UUID primary keys and all five have Row Level Security enabled.

public.load_template_times Reusable time rows belonging to a Load, including sort order and after-hours state. 147 rows

View & RPC Layer

The supplied schema summary documents the core tables and relationships, but it does not include database views or function/RPC definitions. The live application code nevertheless proves that the current system depends on the following database helpers.

RPC

generate_draft_schedule_from_load

Called by single-date and batch Load application. The admin supplies p_schedule_date, p_film_id and p_load_template_id. Observed result: create/refresh a date's draft schedule and generated showtime pattern.

RPC

publish_daily_schedule

Called for both single-date and batch publishing with p_schedule_date. Observed role: publish that date's prepared draft schedule into the live state.

Read View

live_4d_signage_today

Queried by the guest-facing sign with select('*').maybeSingle(). Its returned payload combines schedule identity/timestamps, film presentation data and an aggregated showtime collection for the live sign.

Authentication & Security

All three administration pages use Supabase Auth email/password sessions. The main admin explicitly configures persistent sessions, automatic refresh and a dedicated browser-storage key.

  • The administration interface is hidden unless a valid Supabase session is present.
  • Film Manager and Load Manager use the same authorised 4D admin login model.
  • RLS is enabled on all five public application tables identified by the schema summary.
  • The supplied schema does not include the exact RLS policy definitions.
  • The public sign uses a public/publishable Supabase client and reads the consolidated live view.
Do not place credentials in the Control Room or knowledge base. Passwords, service-role keys, private tokens, secret URLs or other privileged values must never be committed to this public GitHub Pages repository.
Public/publishable browser configuration is intentionally different from a service-role secret. The knowledge base documents the architecture and resource names but does not reproduce credentials or keys.

Supabase client

Administration and public display pages use @supabase/supabase-js@2.

Admin cache

Film/load reference data uses a browser localStorage cache with a current TTL of approximately 10 minutes. Writes that modify films/loads clear relevant cache keys before refresh.

Showtime edit debounce

Both the daily showtime editor and Load Manager wait approximately 650 ms after a time-control change before auto-saving that row.

Default showtime interval

The scheduler and Load Manager use a current default increment of 20 minutes when proposing a new time after the latest existing time.

Public data refresh

The guest-facing sign uses DATA_REFRESH_MS = 10000, or 10 seconds. It compares a payload signature and rerenders the sign when relevant schedule/film/showtime data changes.

Public timer behaviour

  • Advisory rotation: 9 seconds.
  • Testimonial interruption interval: 60 seconds.
  • Testimonial visible duration: 9 seconds.
  • After-hours gate: 5:00 p.m. Vancouver time.
  • Showtime departure/reflow animation: approximately 520 ms.

Accessibility icons

The renderer recognises wheelchair, assistive-listening/audio, captions, service-animal and inductive/hearing-loop categories. It can infer the category from familiar wording when an explicit key is absent.

Troubleshooting

No films appear in the scheduler.

The Showtimes Admin requests only films where is_active = true. Open Film Manager and confirm the required film is marked Active.

No loads appear in the scheduler.

The admin requests only active Load templates. Open Load Manager and confirm the intended Load is active.

Selecting a Load did not change the draft times.

That is expected. The dropdown only changes the preview. Choose Apply Load to Draft to generate/replace the draft showtimes.

Applying a Load erased hand-edited draft times.

Applying a Load is intentionally a replacement operation. Restore the intended Load and make the manual adjustments again, or use a different prepared draft if one exists.

Publish is disabled.

Confirm that the selected date has a draft, the draft has a film assignment, and at least one non-cancelled showtime exists.

Publish reports that pending rows could not be saved.

Inspect the Draft Showtimes rows for a Save failed/error state. Correct the time and use Save Now or Save Pending Showtimes before attempting Publish again.

A newly added showtime is at the wrong time.

A new row is inserted with a default time before the user finishes editing it. Adjust the controls and ensure the row reaches Saved state. If it was just added and should be abandoned, use its Cancel action.

Batch Editor changed draft times on dates that were already prepared.

Batch saving/publishing regenerates the selected dates from the chosen Film + Load and replaces their draft showtimes. Batch Editor should only be used when this replacement is intended.

A default Load cannot be edited.

System-default Loads are deliberately locked. Enable Edit Default for intentional changes, or preferably duplicate the Load and edit the copy.

A Load time says “Already exists.”

Duplicate template times are not allowed within the same Load. Choose a different time.

A poster is missing.

Verify the Film Manager poster code and confirm matching _sm, _md and _lg JPEGs exist under film-posters/web/.

Poster colour sampling fails.

Confirm the medium poster file can be loaded from the expected path. Sampling depends on successfully reading that image into an in-browser canvas.

The live sign does not update immediately after publishing.

Allow for the current 10-second polling cycle. If it still does not update, verify the live schedule, the live_4d_signage_today view and the Kuusoft/NexSigns deployment.

Evening showtimes are missing before 5:00 p.m.

That may be intentional. Times later than 5:00 p.m. are hidden until the after-hours gate opens. A show scheduled exactly at 5:00 p.m. is explicitly exempt from that hiding rule.

The sign says 4D showtimes are unavailable.

The public page did not receive a usable row from live_4d_signage_today, or its query failed. Check that today's schedule is live and then inspect the view/read permissions if the live data exists.

  • The five-table application schema or foreign-key relationships change.
  • The generate_draft_schedule_from_load RPC changes.
  • The publish_daily_schedule RPC changes.
  • The live_4d_signage_today view changes.
